# Contributing — KAIDO E-commerce

Tài liệu dành cho thành viên tham gia phát triển nền tảng. Đọc trước: [README](../README.md), [MODULES](MODULES.md), [ARCHITECTURE](ARCHITECTURE.md), [DATABASE](DATABASE.md).

## 1. Yêu cầu môi trường

- Node.js **≥ 20.9** (xem `.nvmrc`), npm 11.
- Git; tài khoản Supabase cho project dev.
- Không cần Docker. Không dùng thư viện cần biên dịch native.

```bash
npm ci
cp .env.example .env.local
npm run gen:routes
npm run dev
```

Điền `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (project dev), JWT secret và `CRON_SECRET` vào `.env.local`. **Không commit file này.**

## 2. Nhận việc và branch

1. Kiểm tra owner/trạng thái tại [MODULES.md](MODULES.md); cập nhật owner khi được phân công.
2. Đọc `src/modules/mXX-*/README.md` và TODO:
   ```bash
   grep -rn "TODO(MXX" src/modules/mXX-* src/app
   ```
3. Tạo nhánh từ `main`:
   - `feature/mXX-ten-ngan`
   - `fix/mXX-ten-loi`
   - `chore/...`, `docs/...`, `refactor/...`

Không commit trực tiếp lên `main`. Mỗi PR nên tập trung một module hoặc một thay đổi nền tảng.

## 3. Quy ước code

### 3.1. Ngôn ngữ và style

- **JavaScript ES Modules + JSDoc**, không TypeScript. Không thêm `.ts/.tsx`.
- Prettier cấu hình sẵn: `npm run format`; kiểm tra `npm run format:check`.
- ESLint flat config + rule ranh giới module: `npm run lint` phải sạch (warning hiện có không được tăng).
- UI, thông báo lỗi, nhãn trường bằng **tiếng Việt**. Giữ nguyên mã SRS: `M05-F02`, `BR-M05-01`, `API-M05-02`.
- Không rải số nghiệp vụ: đọc từ `src/shared/constants/business-rules.js`; nếu cần cấu hình runtime, đồng bộ `system_settings`.
- Comment chỉ khi giải thích **vì sao** (ràng buộc ẩn, workaround, invariant); không mô tả lại code.
- Không dùng `localStorage` cho access token; không đặt bí mật sau `NEXT_PUBLIC_`.

### 3.2. Ranh giới module

```text
src/app/**            # route mỏng, page, layout
src/modules/mXX/**    # server + client của module
src/server/**         # hạ tầng dùng chung phía server
src/shared/**         # constants, UI, utils, RBAC, auth store phía client
```

- `src/server/**` và `src/modules/*/server/**` bắt đầu bằng `import 'server-only'`.
- Client/shared không import `src/server/**` hay `server/**` của module. Gọi qua API.
- Import chéo module **chỉ** qua `public.server.js` hoặc `public.client.js`; ESLint chặn deep import.
- Thư viện UI dùng chung đặt ở `src/shared/ui`; logic nghiệp vụ UI đặt trong module.
- Component toàn site do module sở hữu (AuthModal → M01, SearchBar → M03, CartBadge/MiniCartDrawer → M04, MegaMenuCategory → M02) và được Header import qua `public.client.js`.
- M03 chỉ đọc M02; M09 sở hữu `CouponService` duy nhất; M08 độc quyền thay đổi tồn kho qua RPC.

### 3.3. Server layer

Luồng chuẩn:

```text
route.js (sinh tự động)
  → server/handlers.js  (nhận ctx, gọi service)
  → server/service.js   (nghiệp vụ, transaction/RPC, gọi module khác)
  → server/repository.js (truy vấn Supabase, không nghiệp vụ)
  → server/validation.js (Zod theo API)
```

- Handler trả dữ liệu thuần hoặc `Response`; `withApi` bọc envelope.
- Dùng `AppError`/`NotImplementedError` với mã trong `error-codes.js`; không trả lỗi thô của Supabase.
- Validation đặt ở biên API (params/query/body); không tin dữ liệu client.
- Thao tác nguyên tử nhiều bảng phải viết hàm PL/pgSQL và gọi `supabase.rpc()`.

### 3.4. Client layer

```text
client/services/*.api.js  # một hàm/API, path đọc từ registry
client/hooks/*.js         # một hook TanStack Query/API, queryKey = mã endpoint
client/components/*.jsx   # component theo SRS UI Components
client/pages/*.jsx        # page khung theo route
```

- Query key dùng mã endpoint (`['API-M04-01', variables]`) để chia sẻ/invalidate cache.
- Hook mutation invalidate đúng key; xử lý loading/empty/error ở component.
- Form dùng React Hook Form + Zod; thông báo lỗi gắn với trường.
- Không fetch trực tiếp Supabase; không hard-code đường dẫn API ngoài registry.
- Trang cần SEO render phía server (Server Component) và ghi rõ trong README module.

## 4. Thay đổi API

Registry là nguồn sự thật:

1. Sửa `src/shared/api-endpoints.js` (mã SRS, method, path, access, roles, input/output, operation).
2. Chạy `npm run gen:routes` — route mới được sinh, route cũ cập nhật.
3. Không sửa tay file có marker `@generated by scripts/gen-routes.js`.
4. Cập nhật handler/validation/service tương ứng.
5. Cập nhật `docs/API_CATALOG.md` (bảng endpoint) và README module nếu hợp đồng đổi.
6. Chạy `npm run check:modules` để chắc mọi endpoint có route.

Quy ước:

- Path `/api/v1`, tham số động `[orderRef]`, `[idOrSlug]`, `[ticketRef]`, `[itemId]`, `[id]`.
- Không đổi tên mã SRS. Nếu SRS thiếu/trùng, ghi vào `docs/OPEN_DECISIONS.md` và giữ alias nếu cần.
- Envelope thành công `{ success:true, data, meta? }`; lỗi `{ success:false, error:{ code, message, details? }, requestId }`.
- Admin API: thiếu đăng nhập → `401`, sai role → `403`.
- Endpoint nội bộ (`internal: true`) không dành cho trình duyệt; không lộ ra client.

## 5. Thay đổi cơ sở dữ liệu

- Chưa có dữ liệu thật: có thể cập nhật `schema.sql` khi thống nhất trong PR.
- Đã có dữ liệu: **không sửa** `schema.sql`; tạo file mới trong `database/migrations/`:
  - Tên `001_mo_ta.sql`, `002_...sql`, tăng dần.
  - Ghi mã SRS ở đầu; chạy được một lần; có kế hoạch rollback/backup.
  - Chạy staging trước production.
- Mọi thay đổi tồn kho phải đi qua 3 RPC; không `UPDATE inventory_stocks` trực tiếp.
- Bảng log bất biến không được UPDATE/DELETE.
- Cập nhật `DATABASE.md` và seed nếu thêm bảng/cấu hình.

## 6. Test

- Framework: **Vitest** (`npm run test`), test đặt cạnh code hoặc trong `test/`.
- Tối thiểu:
  - Validation/BR quan trọng của module.
  - Luồng service với repository được stub (không cần DB thật trong CI).
  - Envelope lỗi/thành công nếu đụng `withApi`.
- Các luồng cần test đặc biệt: khóa đăng nhập, tồn kho đồng thời, timeout 20 phút, chuyển trạng thái đơn, coupon, quota upload.
- Không commit test phụ thuộc thời gian thực/mạng; dùng fake timer/stub.

## 7. Commit và PR

### 7.1. Commit

Conventional Commits, scope là module hoặc `foundation`:

```text
feat(m05): giữ tồn kho nguyên tử khi tạo đơn
fix(m01): chặn đăng nhập sai 5 lần trong 15 phút
docs(m08): cập nhật API catalog và thẻ kho
chore(foundation): nâng cấp Next.js
refactor(m04): tách CouponService client
```

- Một commit một ý; không commit file build, `.env.local`, log, ảnh tạm.
- Không sửa `docs/source/`.
- Không commit bí mật dưới mọi hình thức (kể cả test fixture).

### 7.2. Pull request

Theo `.github/PULL_REQUEST_TEMPLATE.md`, tối thiểu gồm:

- Mã module/FR/BR/API liên quan.
- Mô tả thay đổi và lý do.
- Cách kiểm thử (lệnh + kịch bản).
- Ảnh chụp UI nếu thay đổi giao diện.
- Checklist: lint/test/check:modules/build; docs cập nhật; không có bí mật.

Reviewer kiểm tra:

- Ranh giới module/server-client có bị phá không.
- Validation/BR có đủ, thông báo lỗi tiếng Việt, mã SRS đúng.
- Truy vấn có N+1 hoặc thiếu index không; thao tác nguyên tử đúng RPC.
- Trạng thái loading/empty/error; a11y cơ bản (label, focus, aria).
- Không có thay đổi ngoài phạm vi SRS.

## 8. Definition of Done cho một module

- [ ] Toàn bộ FR/BR/validation của module được triển khai; không còn TODO nghiệp vụ.
- [ ] API thật (không còn 501), đúng registry, đúng quyền 401/403.
- [ ] UI thay thế `ModuleStub`, có loading/empty/error, responsive.
- [ ] Test cho luồng chính + BR quan trọng; CI xanh.
- [ ] README module cập nhật (FR, BR, API, UI, render mode).
- [ ] `docs/API_CATALOG.md`, `DATABASE.md`, `OPEN_DECISIONS.md` cập nhật nếu hợp đồng/quyết định đổi.
- [ ] Không có bí mật, không sửa `docs/source/`.

## 9. Kiểm tra trước khi mở PR

```bash
npm run format:check
npm run lint
npm run test
npm run check:modules
npm run build
```

Nếu `gen:routes` tạo diff, commit các route đã sinh. CI sẽ kiểm tra lại toàn bộ chuỗi này.

## 10. Câu hỏi và quyết định

- Vấn đề mới phát hiện: thêm dòng vào [OPEN_DECISIONS.md](OPEN_DECISIONS.md) với trạng thái `Chưa chốt`, mặc định đang áp dụng và ảnh hưởng.
- Khi team chốt: đổi trạng thái `Đã chốt`, cập nhật code/docs liên quan trong cùng PR.
- Không tự ý mở rộng tính năng ngoài SRS; ghi đề xuất vào OPEN_DECISIONS để bàn trước.
